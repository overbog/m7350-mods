# Development journal

The project started with a spare pocket LTE router nearing the end of useful service. The first question was whether it could run OpenWrt. The inventory identified a Qualcomm MDM9207, 128 MiB of RAM, NAND, and RTL8192ES Wi-Fi. Reading a critical NAND partition was followed by a device hang and physical recovery. Only part of the flash was backed up, and we never validated a full restore. The old vendor BSP, uncertain bootloader behaviour and missing recovery guarantees made a replacement OS a poor fit for this specimen.

We kept the OEM LTE stack and switched to a narrower objective: use the device as a portable VPN router, including access to an Ethernet LAN for Apple device development. A routed VPN was enough for IP connectivity, but it did not provide Ethernet adjacency. We tested L2TP/IPsec for routed access and used it as the transport for optional VXLAN. The direct LTE and routed VPN segments stay separate from the extended LAN. The extended LAN provides its own DHCP.

The OEM Realtek module did not give us a working extra AP. Donor firmware searches identified configurations that referenced virtual APs, but did not produce a compatible module. We adapted the ZX RTL8192ES tree and found that successful compilation did not guarantee a working AP. We reduced the build, enforced a memory threshold and adjusted AP startup and memory recovery. On the bench, separate SSIDs finally accepted clients. Moving the USB interface between bridges exposed stale ARP entries, which we addressed with announcements from the destination bridge.

We built a profile editor and status view over the OEM web stack and an OLED mode menu. VPN startup acquired explicit failure reasons, with diagnostic lines in the system log. The previous research bench verified four scenarios in order: startup after Wi-Fi was idle, wrong PSK, rejected proposal, and a good reconnect. An additional unreachable-server trial verified the failure panel and INFO/ERROR levels. These are specific bench results on EU v5.2 with build 181220. Other revisions and firmware releases are unvalidated.

We also investigated EoIP, a Mac-side relay, and direct VLAN tagging over USB. VXLAN over the existing routed tunnel was the path we could validate end to end. We deferred VLANs and a new kernel. WireGuard feasibility work produced an offline build and did not become the integrated VPN path.
